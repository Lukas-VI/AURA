## 0. 结论摘要（TL;DR）

1. **基线闸门未通过，但不是"假设被证伪"，而是"实现太弱 + 混淆项未排除"。**
   背景码检索 Top-1=0.50%（随机 0.0625%，即 **8.0×**）——统计上显著，但绝对值比"背景像素几乎完全相同"应有的近满命中**低两个数量级**；且**完整码（0.76%）反而优于背景码（0.50%）**，与"背景是唯一来源指纹"的核心叙事不符；检测 AUC=0.5078 完全等于随机。
2. **六条想法里，1 与 3 是"术语大于机制"（包装），2/4/5/6 有实体机制但必须重定位。**
3. **查新结论：7 个主题各自都有成熟先例，必须逐一引用；真正没被人做过的，是"背景作为来源指纹做**图级真实源图检索\*\*，并把源图检索 + 真伪判别 + 攻击类型归因用**因子干预**统一起来"这个组合。\*\*
4. **可成文的骨架**：主线「因子干预式自监督源归因」= 5（训练范式）+ 4（归因）+ 2（检索后端）+ 6（目标函数消融）+ 3 的 benchmark 协议；1 降级为分析章节。

## 1. 基线实测结果（闸门）

### 1.1 训练

`configs/baseline.yaml`：300/100/200 视频切分，`frames_per_video=8`，`epochs_stage1/2=3`，batch stage1=4 / stage2=2。日志：[ffpp\_8f300.log](file:///d:/py/AURA/baseline/logs/ffpp_8f300.log)。

| 阶段     | 读数                                                                                            |
| ------ | --------------------------------------------------------------------------------------------- |
| Stage1 | `loss_h` 0.3192 → 0.1956 → 0.1379；`hash[min,max]` → 0/1；`bit_dev` ≈ 0.01–0.03 → **二值化成功、未坍缩** |
| Stage2 | `quad` 8.07 → 6.50 → 4.11（在学）；**`cls`** **1.3876 → 1.3862 → 1.3857（ln4 = 1.3863，纹丝不动）**       |

`cls≡ln4` 的含义：检测块两个头 DDB 对真/假输出同一个常数，BCE 恰为 `2ln(2)=1.3863`。**DDB 完全没有学到真假判别。**

### 1.2 测试（`test_baseline`）

图库 = 1600 张真实图（200 视频 × 8 帧），查询 = 8000 张伪造图。随机基线：Top-1 = 1/1600 = **0.0625%**，Top-5 = 5/1600 = **0.3125%**。结果：[baseline\_metrics.json](file:///d:/py/AURA/baseline/results/baseline_metrics.json)。

| 指标        | 实测     | 随机基线                     | 倍数         |
| --------- | ------ | ------------------------ | ---------- |
| 背景码 Top-1 | 0.0050 | 0.000625                 | **8.0×**   |
| 背景码 Top-5 | 0.0245 | 0.003125                 | 7.8×       |
| 完整码 Top-1 | 0.0076 | 0.000625                 | 12.2×      |
| 完整码 Top-5 | 0.0336 | 0.003125                 | 10.8×      |
| 检测 AUC    | 0.5078 | 0.5                      | ≈随机        |
| 检测 ACC    | 0.7965 | 全判假 = 8000/9600 = 0.8333 | **低于常数预测** |

评估代码已核查无问题：[retrieval.py](file:///d:/py/AURA/baseline/eval/retrieval.py#L60-L69) 用 `cdist(p=1)`，而 [HashCode](file:///d:/py/AURA/baseline/models/encoder.py#L134-L140) 在 eval 态输出硬 0/1（背景码 64 位），故 L1 即汉明距离；命中判定用 `source_id`，图库/查询同 split，**无泄漏**。

### 1.3 判读（关键）

- **统计显著 ≠ 有用**：8000 次查询下，随机期望命中 5 次、实测 40 次，`p` 小到可忽略。所以按字面标准"显著优于随机"= **是**。

- **但绝对值不可用**：伪造帧与其源真实帧的**背景像素几乎完全相同**，一个正常的背景哈希编码器应接近 100% Top-1。实测 0.50% 说明背景码**几乎不携带背景身份信息**。

- **两个反证**：

  1. **完整码 > 背景码**——若"背景是唯一指纹"成立，背景码应当占优；实测相反，说明前景码也在贡献检索线索（或背景码噪声过大被平均掉）。
  2. **检测 AUC=0.508**——"真伪判别"这一半完全是空的。

- **必须排除的混淆项**（否则结论不可靠）：

  - Stage2 只跑了 3 轮、`quad` 停在 4.11（远未收敛）→ **欠训练**；

  - 背景分支输入是 `x*(1-mask)`，中心被挖成**纯黑空洞**（[hashvae.py](file:///d:/py/AURA/baseline/models/hashvae.py#L79-L91)），编码器可能只在拟合"黑洞形状"而非背景内容。

> **闸门裁决：当前证据不支持直接推进第 5 条立项。** 但归因是"实现弱 + 混淆未排除"，不是"假设被证伪"。需先跑 §9 的四个消歧实验再定。

## 2. 六条想法的逐条评估

| # | 想法                       | 内核                    | 判定                                     |
| - | ------------------------ | --------------------- | -------------------------------------- |
| 1 | t-SNE/UMAP/Isomap 提升可解释性 | 把 hash 码降维画图          | **包装。降级为分析/可视化章节**                     |
| 2 | 向量库 + 连续低维坐标 + 测地/黎曼距离   | 不学 0/1 比特，学连续坐标 + ANN | **可做的子贡献**（度量部分需自证，否则是数学装饰）            |
| 3 | 因果表示学习 / 身份=干预不变坐标       | 因果框架                  | **框架，非贡献**；能产出"因子干预基准"这一实物             |
| 4 | 攻击→哪些坐标移动→归因             | 攻击可归因嵌入               | **最有价值的一条**                            |
| 5 | 攻击无监督对抗训练                | 自监督学背景唯一性             | **主线候选，用对比学习**；有强先例须区分，且当前证据不支持              |
| 6 | 单编码器单阶段 + 正则打散哈希         | 方差-协方差正则替代两阶段         | **工程简化，降级为消融**（本质 VICReg/Barlow Twins） |

**详细理由**

- **1**：t-SNE/UMAP/Isomap 是可视化工具，不是方法。若没有**新的流形结构化目标**（等距约束、测地正则、拓扑保持损失）并证明其带来可测收益，就只是配图，审稿人一眼看穿。

- **2**：连续嵌入 + FAISS/HNSW 替换二值码，报告"精度-速度-存储"权衡，本身是**已知权衡**。诚实做法是**学欧氏度量 + ANN**，把"该用什么度量"当作待验证假设（例如：身份确实有层级结构 → 双曲空间）。卖点在**任务**（deepfake 源检索），不在度量。

- **3**：从观测数据推 SCM / 可识别性做不到，因果只能当叙事外套。真卖点是 FF++ 的 `X_Y` 命名天然给出**两个已知因子**（X=背景来源、Y=人脸供体），可定义"**因子干预式基准**"：改 X 应只动背景坐标、改 Y 应只动前景坐标——用现有 `code_f/code_b` 直接可测。

- **4**：从"观察流形怎么变"升级为"**从坐标漂移反推攻击类型**"，并与源检索绑成 hook（"找到源 + 说出怎么改"）。FF++ 自带 5 种篡改算法标签，**现有数据即可做**。

- **5**：先例是 Face X-ray (CVPR 2020) 及一批自混合自监督取证工作，必须引用并划清界限：**我们做的是"源检索/溯源"，不是伪造检测**。实现坑：当前"攻击"用几何椭圆掩膜合成（[fakegen.py](file:///d:/py/AURA/baseline/data/fakegen.py)），非真换脸，需诚实定义或上真 faceswap 权重。

- **6**：本质就是 VICReg (ICLR'22) / Barlow Twins (ICML'21) 的方差-协方差正则。单阶段端到端是工程简化，不是贡献；作为**消融**有价值。

## 4. 新增两点评估

### 4.1 归因的对抗性（乘法攻击可消除生成模型指纹 → 归因是否可能）

**判定：有建设性，且是必须回应的威胁模型——但对我们反而有利，要正确限定。**

- **必要性**：审稿人若问"一个乘法扰动/压缩就把指纹洗掉了，你的归因方向还有意义吗"，你必须能用实验回答。查新的 #7 一类（RemovalNet / Smudged Fingerprints / Misleading with GAN Fingerprints）已经证明这是**真实且成熟**的攻击面。

- **关键区分（把劣势变优势）**：那些研究针对的是**生成器级指纹**（GAN/DNN 的模型指纹），它确实对乘法扰动、压缩、重采样**脆弱**。而 AURA 的"身份"是**实例级背景内容**（某个具体的房间/场景/背景），**压缩不会把一个房间变成另一个房间**。所以该质疑对"生成器归因"成立，对"**源实例检索**"要弱得多。

- **落地方式**：把它写成**威胁模型 + 鲁棒性指标**，复用现有 [analysis/diagnose.py](file:///d:/py/AURA/baseline/analysis/diagnose.py) 的背景攻击/频域实验，并明确报告"在何种扰动强度下、归因与检索分别退化到何种程度"。

- **风险**：若实验显示源图检索也对轻压缩就崩，那"背景=身份"就必须降级为"低质量/无损场景下的身份"，卖点收窄——**所以这个实验要早做**。

### 4.2 度量学习泛化理论（PAC-Bayes 正则 / 泛化界）

**判定：可以做，但必须"用它导出一个可用的正则项并证明有效"，否则是为了理论而理论。**

- 可行的定位：用泛化界（度量学习/三元组稳定性/谱对比损失可证界，见查新 #5）**作为设计原则**约束嵌入（如控制 Lipschitz / 方差），这与第 6 条的方差-协方差正则是同一件事的两面——**把 4.2 与 6 合并**：提出一个"泛化界动机下的正则项"，并给出**经验泛化间隙**（train/test 差距）的实证。

- **风险**：PAC-Bayes 界通常松、对真实泛化预测力弱。审稿人会攻击界的紧致性。若没有"正则项带来可测收益"的消融，这一节会从加分项变成软肋。

- **建议**：把它放在**附录/补充材料**，正文只留"正则项 + 消融 + 泛化间隙"。

## 6. 实现方案（技术路线）

1. **数据**：FF++ C23 抽帧（`D:/ffpp_frames`）。伪造帧的 `source_path`（原视频同序号帧）与 `donor_path` 已由 [build\_ffpp\_index](file:///d:/py/AURA/baseline/data/dataset.py#L48-L140) 给出——这天然就是"因子标签"，直接可用。
2. **前后景分离**：当前是**固定居中羽化椭圆**（[preprocessing.py](file:///d:/py/AURA/baseline/data/preprocessing.py)）。**必须先评估这个掩膜**：它把背景挖成黑洞、且把头发/头巾错划进背景（掩膜面积占比恒为 0.245）。方案：装 dlib/RetinaFace 换真·人脸凸包，或至少做"掩膜形状消融"。
3. **编码器**：单编码器（替代论文的前后景共享编码器）——把"因子解耦"交给**损失/正则**而非**结构**（对应想法 6）。输出连续低维坐标（对应想法 2）。
4. **头：**

   1. **检测头：** 没有确认是不是要做检测，因为只要检索并比对就可以进行被动检测。不过既然模型能够学习到人脸无关性并归因，那么也可能潜在地能够学会检测
   2. **归因头：从"坐标漂移向量"预测 5 种篡改算法**（对应想法 4 的核心，FF++ 自带标签，现有数据可做）。
5. **训练**：单阶段端到端。损失 = `重构 L2 + 最小熵 + 比特/方差-协方差正则 + 因子干预对比项  + 归因 CE`。
6. **检索后端**：连续码 → FAISS/HNSW（欧氏）；对照组 = 二值哈希 + 汉明；可选实验组 = 双曲嵌入（仅在论证"身份有层级结构"后才上）。
7. **评估**：

   - 检索：`Top-K` **必须对照随机基线 1/N 报倍数**（不是只报绝对值）；

   - 检测：AUC（ACC 在 5:1 不平衡下无意义，需报 AUC + 每类精度）；

   - 归因：多分类准确率 / 混淆矩阵；

   - 因子干预：**改 X / 改 Y 后各坐标块的位移量**（这是"解耦"的直接证据）；

   - 鲁棒性：压缩/缩放/模糊/乘法扰动下的退化曲线。

### 10.3 关键发现：几何椭圆掩膜把人身属性混入"背景"

用 BiSeNet 对 FF++ 帧（真实 / Deepfakes 伪造）做解析，与现有几何椭圆先验并排对比，见 [faceparse\_vs\_ellipse.png](file:///d:/py/AURA/baseline/results/faceparse_vs_ellipse.png)（列序：原图 / 黄=几何椭圆 / 绿=解析脸芯 / 紫=全部人语义 / 蓝=纯场景背景）。

| 掩膜定义                                   | 面积占比（真实 / 伪造） |
| -------------------------------------- | ------------ |
| 几何椭圆（当前基线，`center_ratio=[0.50,0.62]`） | 0.243 / 0.243（**恒定**） |
| 解析脸芯（类 1–12：皮肤/五官/唇）                   | 0.160 / 0.173 |
| 解析全部人语义（类 1–18：含头巾/衣服/脖子）            | ~0.55（目测覆盖） |
| **纯场景背景（仅类 0）**                        | **0.280 / 0.285** |

**这解释了两件事**：

1. **几何椭圆（黄）精确地"错"了**：它把**耳麦、头巾下沿、部分头发**划进"前景"，同时把**下巴/胡须**切到椭圆外归入"背景"——即前景/背景边界与"人脸"毫无关系。基线里 `bg = x·(1−mask)` 的"背景"因此同时装着**人脸残片 + 人身配饰 + 真场景**，来源指纹被稀释。
2. **正确的切分应当是"人语义 vs 纯场景"**：`fg = 类 1–18`（人脸 + 头巾 + 衣服 + 脖子，即一切属于"人"的像素），`bg = 类 0`（只剩窗外/墙面等**真场景**）。这样 `bg` 才是"房间指纹"，才符合"背景是来源指纹"的叙事；而当前基线恰恰把"人"的一部分混进了 `bg`。

**落地方式**（对应 §9.2 "真·人脸分割替换几何椭圆"）：在 [preprocessing.py](file:///d:/py/AURA/baseline/data/preprocessing.py) 的 `FaceBackgroundSplit` 里把 `face_bbox` 的几何先验换成 BiSeNet 前向（`79999_iter.pth` 零额外依赖），`mask = 类1–18` 的并集。**这是当前性价比最高的一个改动**，且与"不改检测头（DDB）"的约束不冲突。

### 11.3 检索/检测对比（同一测试协议：1600 真实图库 / 8000 伪造查询）

| 指标 | 旧基线（几何椭圆） | 本轮（BiSeNet 解析） | 变化 | 相对随机基线 |
| --- | --- | --- | --- | --- |
| 背景码 Top-1 | 0.0050 | **0.2428** | **48.6×** | **388×**（随机 0.0625%） |
| 背景码 Top-5 | 0.0245 | **0.6443** | **26.3×** | **206×**（随机 0.3125%） |
| 完整码 Top-1 | 0.0076 | **0.3314** | **43.5×** | 530× |

| 检测 ACC | 0.7965 | 0.5289 | — | 两者都不可用 |

> ACC 说明：旧基线 0.7965 **低于**"全判假"常数预测 0.8333，本轮 0.5289 也≈随机 —— 该指标在此类不平衡设定下无鉴别力，**只认 AUC**。

### 11.4 结论（正负各一条）

1. **正向：掩膜假设成立，检索被解锁。** 仅把"背景"从"人+配饰+残片+场景"的混合物改成"纯场景（类 0）"，背景码 Top-5 就从 2.5% 跳到 64.4%（随机 0.31%），Top-1 从 0.5% 到 24.3%。这**直接支撑 AURA 的核心叙事**：背景确实是可用的来源指纹，此前检索几乎失效的原因在于**背景指纹被稀释**，而非假设错误。至此 §1.3 的"背景码几乎不携带身份信息"判读被推翻，§9.1 的 E2 掩膜消融实验也已由本轮给出答案。
2. **负向：检测（DDB）依旧学不动，且与掩膜无关。** `cls` 三代实现（单哈希 / 几何椭圆 / BiSeNet 解析）恒为 ln2，本轮 AUC 0.5166 仍等于随机。这与 §8 记录的"前景四元组项 vs 检测 BCE 的目标冲突"一致：**DDB 只读前景哈希**，而前景的四元组项/最小熵会把真假前景压到相近码位；掩膜改善的是**背景纯度**（作用于检索），对前景上的检测目标无能为力。受"不改 DDB（论文权威）"约束，此冲突需从**损失编排/训练范式**侧解，而非检测头结构。
3. **遗留反证仍在**：完整码（0.3314）继续优于背景码（0.2428），与 §1.3 的观察一致 —— 前景码仍在贡献检索线索。若"背景是唯一来源指纹"是严格命题，此现象仍需解释（可能因为查询/图库同序帧的前景也高度相关，或背景码被前景码的加性补偿校正）。列为待验证项。
