## 0. 先划界：复现的基线(HashVAE) vs 自建的 AURA —— 然后才谈涨点

> 本节是本版**新增的前置约定**。在展开任何 idea / 涨点之前，先把"我们在**复现**什么"与"我们要**自建**什么"分开。

### 0.1 三阶段定位（顺序不可倒）

```
【阶段 1 · 现在，进行中】复现基线
  HashVAE（Liu et al. 2026）按论文重写 —— 这是**别人的工作，不是我们的贡献**。
  论文未开源，故这属于"忠实复现"，目标是拿到可信的对照数字。

【阶段 2 · 下一步】界定 AURA
  用一张表说清 AURA 相对基线的**每一处增量**，判定哪些构成"贡献"、哪些只是"复现偏差"。

【阶段 3 · 其后】涨点
  表征 / 后端调优（#4/#9 等），**服务于前两者**，不能先于前两者。
```

**一句话：现在跑的 100% 是别人的基线；AURA 目前一行代码都还没有（`aura/` 只有一个占位 `__init__.py`）。** 所以在谈涨点之前，必须先钉死两件事：(1) 基线复现到什么程度算**忠实**；(2) AURA 相对基线**改了什么、为什么这些改动算贡献**。

### 0.2 三类别界定表（哪些是论文的、哪些是我们的、哪些是偏差）

| 类别 | 具体项 | 归属 | 叙事处理 |
| --- | --- | --- | --- |
| **A. 论文原样复现**（对齐即算完成，**不是**我们的贡献） | 前后景分离 + 共享编码器（`C=C_f+C_b`）；**掩膜（论文用"分割式"方法划分前后景）**；DDB 只读前景哈希（式 12）；四元组前景/背景分项、平方 L2、α=β=0.5（式 15）；重构 L2 分项（式 9）；最小熵比特损失（式 10/11/16）；两阶段训练；方案 A 容量规格（M=5 / D=5 / 64ch / aff 512 / hash 2048） | **论文** | 只作"复现对象"，引用论文即可，**绝不写成贡献** |
| **B. AURA 的主动改动**（→ **候选贡献**，**只在任务/协议层**） | ③ 任务重述 + 评测协议：收缩为纯检索、命名"换脸源图检索" + Recall@K / mAP + open-set 拒识 + 视频级折叠 + 六档退化 | **AURA** | 贡献 ⑩② |
| | ④ `X_Y` 因子标签 → 溯源图 / 因子干预 | AURA | 贡献 ① |
| **C. 复现偏差 / 实现替换**（诚实标注，可能影响保真度） | 掩膜：论文用分割式方法，我们改用 BiSeNet 19 类解析 —— 属"同类机制的不同实现"，**不是**贡献；掩膜从模型内固定 buffer 改为逐样本随数据流入（工程细节）；`hash_proj` 用"逐比特 BN+Tanh+LayerNorm"而非式 7 的 softmax；额外加了"比特平衡"工程项；`q+1` 用自包含合成换脸而非 SimSwap；早期几何椭圆掩膜（已废弃） | **需逐条标注** | 进"与论文差异"表，并说明**是否影响结论** |

> **纠正（2026-10-16，据用户反馈）**：此前把 BiSeNet 掩膜写成"AURA 的第一个主动贡献（B①）"是**错的** —— HashVAE 原论文本身就用**分割式**掩膜来分前后景，BiSeNet 只是"同机制的不同实现"，**属 C 类，不是贡献**。其带来的 48.6× 跃迁（背景码 Top-1 0.0050 → 0.2428）应读作 **"此前几何椭圆是欠保真的复现，改回分割式掩膜后保真度提升"** —— 它**加强的是复现保真度叙事**，而非贡献叙事。
>
> **由此得到的路线结论**：去掉掩膜这个"假贡献"后，**AURA 真正的增量只剩任务/协议层（⑩①②）** —— 即"把任务重述清楚 + 给出可复现的评测协议 + 溯源图 / 因子干预"。模型结构侧（编码器 / 掩膜 / 检测头）**没有**我们的贡献；这必须在论文里说清楚，别把复现当发明。

### 0.3 AURA 怎么建（此前从未写清）

**结论先行**：AURA 的增量**不在模型结构侧** —— 掩膜、编码器、检测头都属基线复现（见 §0.2 的 A/C 类）。AURA 的增量在**任务定义 + 评测协议 + 溯源层**。所以"AURA 模型"≈"忠实复现的基线模型（纯检索模式）+ 任务重述 + 协议 + 溯源"，而**不是**一个新网络。**别把复现当发明。**

**保留不动的骨架**（这也是论文的，不是我们的）：共享编码器 + 前景/背景分离 + 双模态哈希码 `C = C_f + C_b`。

**AURA 相对基线的增量清单（全在任务/协议层）**：

| 序 | 增量 | 从（基线） | 到（AURA） | 归属 |
| --- | --- | --- | --- | --- |
| 1 | 任务重述 | 论文：检索与检测并列 | **收缩为纯检索**（检测降为对照，AURA 主线可剔除） | 框架（⑩ 的前提） |
| 2 | 检索粒度 | 论文算法 1 的两阶段 | **图级源图检索**，并可折叠到视频级 | ⑩ |
| 3 | 监督扩展 | 四元组（相似度定义） | 四元组 + **`X_Y` 因子标签 → 溯源图 / 因子干预** | ① |
| 4 | 评测 | 单查询 Top-K | 冻结协议（§5）+ open-set 拒识 + 六档退化 + 随机基线倍数 | ⑩② |
| — | 掩膜 / 编码器 / 检测头 | — | — | **属基线复现（C 类），不列为 AURA 增量** |

**构建顺序（与 §6 的 P0/P1 对齐）**：

- **步骤 0（P0）**：**不动 AURA**；跑完基线 + 通过保真度裁决（T0.0，含把掩膜对齐到论文的分割式思路）。
- **步骤 1（P1a）**：**AURA-v0 = 基线的纯检索版** —— 模型骨架与掩膜**沿用**（因为那是复现），只**砍掉检测分支、把目标换成纯检索**；代码迁入 `aura/`，便于后续只在"协议 / 溯源层"加东西。
- **步骤 2（P1a）**：#11 三档输入与 #12 掩膜纯度 → 定位为**复现保真度 / 机制验证**（回答"检索靠哪个模态""掩膜纯度影响多大"），**不是贡献**。
- **步骤 3（P1b 及以后）**：真正的新东西才落进 `aura/` —— 溯源图（①）、退化协议（②）、open-set（⑩）；表征侧涨点（#4/#9）排在其后。

**为什么这个顺序是关键**：AURA 的贡献是"**任务重述 + 可复现协议 + 溯源 / 因子干预**"，**不是**模型结构改动，也**不是**"把 Top-1 从 0.24 调到 0.30"。把涨点写在最前面，等于把论文的贡献点自己埋掉。

### 0.4 现况摘要（原 TL;DR）

1. **限定 Retrieval 是一次正确的收缩**：检测分支已被两次独立裁决为"信息缺失"（§11.6 探针：`h_f` test AUC 0.5105/0.5227），继续投入是沉没成本；而检索侧已被掩膜改造证明**假设成立且可用**（背景码 Top-5 0.6443）。
2. **查新发现一个必须正面处理的先例：ViTHash**（arXiv 2112.08117《Vision Transformer Based Video Hashing Retrieval for Tracing the Source of Fake Videos》）。它已经把"从伪造视频找回原始视频"做成了任务。**我们所有提案都必须先与它划清界限**（它：整帧、视频级、无前背景分离、无退化协议、无溯源图）。
3. **推荐主力三件套（互不冲突、可拼成单篇）**：`①溯源图/近重复链接` + `⑩任务与评测协议定义` + `②退化鲁棒协议`；**backup 两件**：`④多帧/视频级聚合`（1 周）与 `⑨度量学习涨点`（保底牌）。
4. **本轮技术上有三处"必须做但没人做"的便宜活**：① 冻结一套**源图检索协议**（含随机基线倍数、open-set 拒识、视频级折叠）；② 用**真实退化**（JPEG/缩放/裁剪/重编码）把"背景指纹可用"从实验室条件推进到**可用系统**；③ 用 `X_Y` 因子标签把**溯源图**做出来（零标注成本）。
5. **不对称收益提示**：`⑩`+`②` 的工程量各约 2-3 周、风险低、几乎是"必得"的分；`①` 的贡献上限最高（新任务级贡献），但需要先确认"同背景簇"在嵌入空间里真的分得开 —— 已列为 `P2` 的 kill 判据。

## 1. 范围收缩后的取舍（明确写进论文 framing）

| 项 | 收缩前（基线复现阶段） | 收缩后（AURA 主线） |
| --- | --- | --- |
| 检测（DDB / AUC） | 与检索并列的贡献之一 | **降级为附带对照**：只报一条 AUC 说明"本方法不主打检测"；不再花时间调 |
| DDB 结构约束（论文权威，不改） | 硬约束 | **仅约束 baseline 复现**；AURA 主线不受此约束（可直接砍掉检测分支） |
| 前后景共享编码器 | 论文原样 | 保留（这是"背景=指纹"的结构前提） |
| 评测对象 | 图库 1600 真实图 / 查询 8000 伪造图 | **冻结协议见 §5**，并扩展规模、分层报告 |
| 贡献落点 | 检索 + 检测 + 归因 | **检索 + 溯源 + 鲁棒性协议** |

> 一句话 framing：*AURA 不是又一个 deepfake 检测器，而是在回答"这张伪造图是从哪张真实图来的、以及它属于哪一批伪造"。*

| --- | --- | --- | --- | --- | --- |
| 1 | **溯源图 / 近重复链接**：把"伪造图→真实源帧"的边聚成簇，输出 provenance graph | ★★★ | ★★★ | 3-4 周 | **主力** |

| # | 提案 | 理由 | 工程量 |
| --- | --- | --- | --- |
| 11 | **"完整码 > 背景码"反证的消歧**：跑"只喂背景 / 只喂前景 / 整图"三档，判断前景码贡献的是"真线索"还是"加性补偿的噪声" | 这是 §11.4 遗留反证；**直接决定** "背景是唯一指纹" 这一叙事能否写进正文 | 3-5 天 |

## 4. 推荐组合与差异化要点

### 4.1 主力 / backup 定档

```
主干（单篇完整故事）—— 顺序：先复现、后界定、再涨点：
  基线与裁决    → 复现基线并给出保真度裁决（§0、P0 的 T0.0）
  AURA-v0 定义  → 基线的纯检索版（骨架/掩膜沿用，砍掉检测），落到 aura/（§0.3、P1a）
  ⑩ 任务与协议  → **贡献主体**：定义问题、给出评测合法性（与 ViTHash 划界）
  11+12 验证    → 钉死"检索靠哪个模态 / 掩膜纯度影响多大"（**复现保真度证据，非贡献**）
  ① 溯源图      → 从"单查询检索"升级为"语料级溯源"（贡献上限最高）
  ② 退化基准    → 从"实验室"推进到"可用系统"，暴露真实边界

backup（按 G3/G4 的成败决定是否上）：
  ④ 多帧聚合    （① 的自然增量，1 周）
  ⑨ 度量学习    （保底涨点：难负样本 + 重排 + query expansion）
```

### 4.2 与 ViTHash（arXiv 2112.08117）的差异化（**必须显式对比**）

| 维度 | ViTHash | AURA |
| --- | --- | --- |
| 检索粒度 | **视频级**（整段视频哈希） | **图级**，且可折叠到视频级（两条都报） |
| 输入分区 | 整帧，无前后景分离 | **背景区域特化**（BiSeNet 纯场景），前景码/背景码分开评估 |
| 监督 | Hash Triplet Loss（配对监督） | 利用 FF++ `X_Y` **因子标签**（背景来源 X / 人脸供体 Y），可做因子干预与溯源 |
| 评测 | 单查询 Top-K | 单查询 Top-K **+ open-set 拒识 + 语料级溯源图** |
| 退化 | 无 | **有**（JPEG / 缩放 / 裁剪 / 重编码协议） |

> 若这一页对比写不出来，说明本轮提案没有增量 —— 这是最优先要保证的一件事。

## 5. 评测协议（冻结 v1，所有实验共用）

| 项 | 规格 | 备注 |
| --- | --- | --- |
| 图库 | 测试 split 的**真实帧**；当前 1600（200 视频 × 8 帧） | 规模扩展见下 |
| 查询 | 测试 split 的**伪造帧**；当前 8000 | 5 种篡改算法**分层报告** |
| 命中 | 查询的 `source_id`（背景来源真实帧）落在 Top-K | 与论文 Algorithm 1 情形(1) 一致 |
| 主指标 | Recall@1/5/10、mAP@10 | **必须并列随机基线倍数**（1/N、K/N） |
| 折叠指标 | 视频级 Recall@1（同视频任一帧命中即算） | 缓解"8 帧/视频"的帧级歧义 |
| 拒识 | open-set：把一部分查询的源图**从图库移除**，报 AUC / TPR@FPR=1% | 新增，ViTHash 没有 |
| 退化 | `clean / jpeg50 / jpeg20 / scale0.5 / crop0.5 / reencode` 六档 | 只作用于查询；图库可同退化或保持干净（两种都报） |
| 规模 | `1600 / 4800 / 8000` 三档图库 | 扩大图库 = 重新划分 split（如 300/100/600），**模型需重训**，故列为 P3 可选 |

**规模扩展的代价**：把测试视频从 200 提到 600 会把训练视频从 300 压到 200 以内（总 1000 个真实视频）。若要在不牺牲训练量的前提下扩大图库，可考虑"训练用 1-300 视频的帧、图库用 301-1000 的视频"这种 **train/gallery 不相交**的划分 —— 这本身就是一条可写的协议贡献（更接近真实取证场景：**图库是海量第三方素材，不是测试集**）。
